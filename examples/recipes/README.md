# Runnable decision recipes

These examples turn model responses into an explicit recommendation. They **do not update tickets, approve expenses, or make payments**. Each prints JSON records and can be adapted to your application after evaluation.

From a clone of this repository, install one backend:

```bash
pip install -e '.[mlx]'       # Apple silicon, text
# OR
pip install -e '.[torch]'     # NVIDIA / CPU / Apple MPS; required for images
```

In one terminal, start the text server:

```bash
jev-style serve
```

In another terminal, run the commands below. They use `http://127.0.0.1:8765` by default; `--url` changes it. The examples send data only to the URLs you choose, without an Authorization header. The browser demos are also available at [JevStyle](https://jevstyle.com/?utm_source=github&utm_medium=recipe&utm_campaign=start_here) and [Hugging Face](https://huggingface.co/spaces/chaoliangUNSW/jev-style-2b).

## Support-ticket routing

```bash
python examples/recipes/ticket_router.py
python examples/recipes/ticket_router.py --min-probability 0.9
```

Each record includes the proposed team, its probability, the model ID, and a `decision`: either that team or `human_review`. A failed request also goes to review. The bundled [12 tickets](data/tickets.jsonl) are hand-written synthetic examples, evenly split across billing, shipping and returns. They contain no customer data.

Use `--input your_tickets.jsonl` with one object per line:

```json
{"id":"ticket-1","text":"The parcel has not arrived.","expected_team":"shipping"}
```

`expected_team` is optional and is used only in reporting; it is never sent to the model. Allowed teams are `billing`, `shipping` and `returns`. Edit `TEAMS` and `QUESTIONS` in `common.py` to match your taxonomy.

## Fallback to another model

Start a second server in another terminal. The model choice below is an example; measure whether it helps your data:

```bash
jev-style serve --release 2b --port 8766
```

Then run:

```bash
python examples/recipes/fallback_router.py --fallback-url http://127.0.0.1:8766
```

The primary sees every ticket. Only low-probability answers or failed requests go to the second server. Its answer must also meet the threshold, otherwise the result remains `human_review`. Omitting `--fallback-url` routes uncertain cases directly to review. A remote fallback receives the original ticket text, so choose an endpoint appropriate for your data.

The summary reports primary acceptances, fallback calls, final coverage, accuracy among accepted labelled items, and client elapsed time. Latency includes the first request, any fallback request and HTTP overhead; it excludes server startup and downloads. A lower fallback-call count is **not** a cost-saving measurement. The small synthetic dataset cannot establish general accuracy, calibration or production savings.

The threshold is the maximum option probability, **not** the API's normalized `confidence` field. `0.8` is an example, not an 80% accuracy guarantee. Select thresholds on separate validation data, then assess them on held-out examples; use [`jev-style eval`](../../README.md#evaluate-on-your-own-data) for a more complete evaluation.

## Receipt review

Start a **2B v4 PyTorch** server (stop the text server first or choose another port):

```bash
jev-style serve --release 2b --backend torch
python examples/recipes/receipt_review.py
```

The bundled [synthetic receipt](data/synthetic_receipt.png) shows a EUR 60 meal. The example policy says meals strictly above EUR 50 need manager review. The response contains the model's probability and a review recommendation. A low probability is **not** an automatic approval. Verify the image and the policy before making a financial decision.

```bash
python examples/recipes/receipt_review.py --image /path/to/receipt.png
```

The script checks that the server advertises image support. v3, MLX and GGUF builds are text-only. Inputs must be still PNG/JPEG, 280–1,568 pixels per side and at most 16 MiB each; the server validates these limits. The SDK sends the required image header and references the image through `state`.

To validate the bundled fixture without running a model:

```bash
pip install Pillow
python examples/recipes/receipt_review.py --check
```

The fixture is generated by `python examples/recipes/data/make_receipt.py` (Pillow). It is a test document, not a valid tax invoice.

## Check the plumbing without downloading weights

```bash
pip install -e '.[dev]'
python examples/recipes/ticket_router.py --fake
python examples/recipes/fallback_router.py --fake
python examples/recipes/receipt_review.py --check
pytest tests/test_recipes.py -q
```

`--fake` produces deterministic, meaningless model scores. Its summary is labelled `fake_plumbing_only`, and accuracy is intentionally omitted. Image contract tests also use a deterministic stand-in; they do not demonstrate image recognition quality.
